## 1. 三个对照条件（怎么构造，为什么是这三个）

| 条件 | 构造方式 | 它代表什么 | 为什么必须放在协议里 |
|-|-|-|-|
| **C0 裸做法下界** | `scripts/bare_baseline.py`：读 `case.json` → 网格排版 → 写 `figure.svg` 与两个 **0 字节**占位 `figure.png`/`figure.pdf` | "不加载 Skill、也不额外努力"时的产物形态 | 没有它，"加载后更好"无从比较 |
| **C1 本 Skill** | `scripts/main.py` 完整流水线（证据抽取 → SIR → 布图 → 渲染 → 校验 → 契约） | 本包的交付路径 | 被检验的对象 |
| **C2 同代码关掉门禁** | `scripts/main.py --rules <空对象 json>`：**同一份代码**，只把规则资产置空 | 把"算法本身"与"门禁带来的增益"分开 | 只有 C2 存在，才能回答"增益是来自算法还是来自审计" |

**C2 为什么公平**：C2 与 C1 唯一的差别是一个 CLI 参数，两者产物内容
（`figure.svg`/`layout.json` 的 sha）完全相同——这一点在 §4 的记录里被实测确认。
因此 `Q3` 的差**只能**归因于规则审计，不能归因于别的。

**C0 的定位必须说清楚**：它是一个**可执行的下界**，不是"某个模型的真实行为录像"。
真实 agent 在无 Skill 时的表现可能更好也可能更差。C0 只回答一个问题：
*"当那些环节被拿掉、且不做任何额外努力时，产物会是什么样？"*
本协议**不对任何模型的真实分数作断言**，平台提供的白板才是相对比较的权威依据。

## 2. 必须固定住的四个条件（不固定就没有公平）

| # | 固定项 | 本协议怎么做 | 不固定的后果 |
|-|-|-|-|
| F1 | **同输入** | 三个条件读**同一份** `case.json`；记录其 `sha256` | 输入不同，指标差无法归因 |
| F2 | **同任务书** | 同一份 `task.md`；若某条件不支持读 task，视为该条件的固有劣势并在记录里标注 | 任务要求不同 = 不是同一道题 |
| F3 | **同运行环境** | 同机、同 Python、同依赖版本（Pillow/reportlab/字体） | 渲染差异会被误读成方法差异 |
| F4 | **同预算** | 每条件**只跑一轮、不重试**；耗时按单轮 wall-clock | 多次重试取最好成绩 = 选择性报告 |

> 本包实测环境：Windows 11 (10.0.22621) · Python 3.13.9 · Pillow 12.3.0 ·
> reportlab 5.0.0 · cairo svg/svgwrite 不可用（本包不需要）。
> 换环境重跑，**数值会变、结论方向不应变**；若方向变了，把两条记录都保留。

## 3. 预注册指标（先定义，再测量）

### 3.1 为什么要"预注册"

如果先看图再挑指标，任何包都能找出"我更好"的那一列。所以本协议要求：
**指标、算式、阈值在看结果之前就写死**，测量只做"填数"。
下面每个指标都给出**算式**（可照抄）、**判定规则**（机器可判）、**测量对象**（哪个字段）。

### 3.2 质量指标（6 项）

| 指标 | 算式 | 判定规则 | 测量对象 |
|-|-|-|-|
| **Q1 来源绑定率** | 有 `locator` 的 `evidence.items` 条数 ÷ (输出实体数 + 输出关系数) | = 1.00 为达标；< 1.00 说明有图面元素无法追溯 | `result.json.evidence.items[].locator` |
| **Q2 断头端点外露数** | 输出关系里 `from`/`to` 不在输出实体集合内的条数 | = 0 为达标；> 0 说明画了不存在的连接 | `result.json.relations` × `entities` |
| **Q3 违规暴露数** | `len(verify.errors) + len(verify.warnings)` | 与输入缺陷量比较（见 Q3b） | `result.json.verify.errors/warnings` |
| **Q3b 缺陷召回** | Q3 ÷ 预先注入的缺陷数 | 越高越好；**C0 恒为 0**（无审计） | 需人工构造带缺陷的输入 |
| **Q4 可编辑源文件** | `verify.checks.editable_text` 且 `verify.checks.entity_groups` | 两者皆 true 为达标 | `result.json.verify.checks` |
| **Q5 真实导出件** | `figure.png`/`figure.pdf` 字节数 > 0，且 PNG 可解析、尺寸 == 画布×DPI | 两者都 > 0 为达标；0 字节 = 占位，**不算真实导出** | 输出目录文件字节 |
| **Q6 状态诚实性** | `verify.ok=false` 时 `status` 是否为 `partial`/`failed`；`verify.ok=true` 时是否为 `success` | 一致为达标 | `result.json.status` × `verify.ok` |

### 3.3 效率指标（4 项）

| 指标 | 算式 | 怎么读 |
|-|-|-|
| **E1 单轮耗时** | 一次完整运行的 wall-clock（秒） | 只用于**同条件跨版本**比较，不要跨机器比较绝对值 |
| **E2 产物字节** | 输出目录递归总字节 | 反映"产出了多少真东西"；**更大不等于更好**，要配合 Q5 读 |
| **E3 人工干预步骤** | 到"可交付"还需人工做几步（列清单） | 这是**"少做多少事"**，不是"跑多快"——真正的效率增益在这里 |
| **E4 返工轮次** | 修改一处标注要重做多少（重画 = 1 轮） | 本包用 `--merge` 把常见返工压到 0 轮 |

> **本协议明确区分"运行效率"与"人工效率"**。前者本包的实测结论是**没有增益**（§4.3），
> 后者有增益。把两者混在一起说"效率提升"是不诚实的，本协议不这么做。

## 4. 本包实际跑过的对照记录（2026-11-22）

> 复现命令就写在每小节里；机器可读原始数据在 `references/comparison-data.json`。
> 两个合成案例：`clean`（8 实体 / 7 关系，材料自洽）与
> `defective`（12 实体 / 13 关系，**预注入 5 类缺陷**：断头关系、非法类别、
> 缺 `source`、重复 id、非法关系种类）。

### 4.1 命令（逐字可复跑）

```bash
SKILL_DIR=<本包目录>
CASE=<case.json>; TMP=<临时目录>

python "$SKILL_DIR/scripts/bare_baseline.py" --case "$CASE" --out "$TMP/c0"        # C0
python "$SKILL_DIR/scripts/main.py" --case "$CASE" --out "$TMP/c1"                 # C1
printf '{}' > "$TMP/empty-rules.json"
python "$SKILL_DIR/scripts/main.py" --case "$CASE" --rules "$TMP/empty-rules.json" --out "$TMP/c2"  # C2

python "$SKILL_DIR/scripts/gain_probe.py" --result "$TMP/c1/<case_id>/result.json" --baseline "$TMP/c0"
python "$SKILL_DIR/scripts/check.py" "$TMP/c1/<case_id>/result.json"
```

**确定性**（两个案例各跑两轮 C1）：`figure.svg`、`layout.json`、`evidence.json`、
`verify_report.json` **全部逐字节一致**（4/4 × 2 案例）。
同时 C1 与 C2 的 `figure.svg`/`layout.json` **sha 完全相同**（defective：`46dcf42a...` /
`e661e8c3...`），只有 `verify_report.json` 不同（`6ab17444...` vs `1c04d7a5...`）——
这正是 C2 条件的构造意图：**算法输出不变，审计结果改变**。

### 4.3 效率结论：一条负面结果

| 指标 | C0 | C1 | 结论 |
|-|-|-|-|
| E1 单轮耗时 | 0.100–0.112 s | **0.497–0.593 s** | **C1 慢约 4.4–5.3 倍** |
| E2 产物字节 | 2.5–3.8 KB | 78–105 KB | C1 大 27.6–31.5 倍（因为产出了真的 PNG/PDF） |

**所以本包不声称"运行效率提升"。** 慢与大的原因很直接：C0 只做排版与写文件，
C1 还做了证据抽取、确定性布图、SVG 渲染、PIL/reportlab 导出、规则审计与契约自查。

真正的效率增益在 E3/E4 两列，它们是"**人工要补多少**"：

| 指标 | C0 | C1 | 依据 |
|-|-|-|-|
| E3 人工干预步骤 | ≥ 3 步：①补每个元素的出处 ②检查连接方向是否成立 ③真正渲染导出（C0 的 PNG/PDF 是 0 字节） | **0 步** | C0 的产物里没有 `evidence`/`verify` 字段，也没有可用的 PNG/PDF |
| E4 返工轮次 | 1 轮（改一处标注要重画） | **0 轮**（`--merge` 同名替换 + 新 id 追加，动 `change_record`） | 见 `examples/EXPECTED-OUTPUT.md §5` |

> **诚实的总结**：本包的增益是**质量与可靠性**（Q1/Q2/Q5/Q6 从"不满足"变"可机器验证地满足"，
> Q3 在缺陷输入上多抓 3 条），而不是**运行速度**。任何"效率提升 N 倍"的说法都与本包实测不符。

## 5. 第三方怎么用这份协议

1. **核本包**：按 §4.1 的三条命令跑一遍，用 `gain_probe.py` 复算 Q1–Q6，
   与 §4.2 的表对拍。数字对不上 → 先查环境（F3）与输入 sha（F1），再查结论。
2. **核别人的同类包**：`gain_probe.py` **不 import 本包任何模块**，
   只读 `result.json` 的公开字段；只要对方的 `result.json` 也有
   `entities`/`relations`/`evidence`/`verify`，就能算出同一套 Q1–Q6。
3. **搬到别的题**：把 Q1（来源绑定）/Q2（断头）/Q3（违规暴露）/Q5（真实导出）/
   Q6（状态诚实）换成那道题的对应概念，协议结构（条件 × 固定项 × 预注册指标 × 记录）不变。
4. **只报能算的**：协议里没有"提升明显"这种话；每个数字都能被 §4.1 的命令重算出来。
   如果某个指标在你的环境里算不出来，**写"未测"而不是写估计值**。

## 6. 协议自身的已知局限（诚实声明）

- **样本量小**：2 个合成案例 × 3 条件 × 1 轮。C0 是"可执行下界"而不是真实 agent 录像，
  所以本协议证明的是"这些环节的价值"，**不是**"本包一定比某个 agent 好 X 分"。
- **C0 的 SVG 含 `<text>` 计数为 0 是设计使然**：它只画 `<rect>` + 无文字标签，
  这不是"所有裸做法都会这样"，而是"下界实现长这样"。
- **E3/E4 是清单式指标**，不是秒表式指标；它们的裁决需要人读产物（清单在 §4.3 给出）。
  之所以仍然放进协议，是因为"少做几步"正是本题效率增益的实义。
- **Q3 依赖缺陷输入**：干净输入上 C1 与 C2 的 Q3 都是 0（§4.2），
  所以门禁的价值**只能**在带缺陷的输入上被量出来。这条限制让 Q3 必须配合 Q3b 一起读。
- 本协议不覆盖多案例统计显著性（无重复实验设计）；它覆盖的是"指标定义 + 单轮可比 + 可复算"。

## 1. 实际执行的命令序列

```bash
# 每个案例 c ∈ {clean, defective}
```

## 0. 三层机制速览

| # | 机制 | 一句话 | 没有它会怎样（可观测） |
|-|-|-|-|
| M1 | **证据中间层**（evidence-first） | 图面元素在进入渲染之前，先落成一份带 `locator`+`quote`+材料 `sha256` 的清单 | 元素只剩名称，无法回答"这个盒子出自材料哪一句" |
| M2 | **确定性布局与规格探针** | 布局是纯函数；`spec_sha16` 把"同输入 ⇒ 同布局"变成可对拍的指纹 | 同输入两次可能给出不同图面，结论无法被别人复现 |
| M3 | **规则资产的机器审计** | 连接语义做成**可编辑的 JSON 资产**，由 `svg_verify.py` 逐条审计，error 级强制降级 | 连接错、方向反、编号断都只能靠肉眼；且规则无法被第三方扩展 |

## 1. M1 证据中间层：没有它，图面就无法回溯

**它是什么**：`scripts/gain_evidence.py` 在布图之前先跑一遍，产出 `evidence.json`：
每条实体/关系一个 `{id, type, ref, locator, quote}`；同时给每个输入文件记
`sha256`/`size`/`role`。这份清单回显进 `result.json.evidence`，
后续 `data_mapping` 与 `element_traceability` 都从它派生。

**没有它会怎样**（用 `bare_baseline.py` 对照，同一份 8 实体 / 7 关系输入）：

| 观测量 | 无 M1（下界实现） | 有 M1（本包） |
|-|-|-|
| 图面元素的出处信息 | 只有 `<text>` 里的名称 | 每元素一条 `locator`（材料章节）+ `quote`（原文片段） |
| 来源绑定率（有 `locator` 的元素 ÷ 元素总数） | **0.00**（产物里没有这个字段） | **1.00** |
| 「用的是哪一版材料」 | 无从回答 | `evidence.source_files[].sha256` 直接给出 |
| 元素 ↔ 材料双向回溯 | 不可能 | `element_traceability[]` + `evidence.items[].ref` 互指 |

**边界（它做不到什么）**：M1 只保证"出处字段存在且指向真实读到的文件"；
它**不判断**引文是否贴切（那需要人读），也**不阻止**一条断头关系被写进材料
（断头由 M3 处理）。所以 M1 的价值是"让复核成为可能"，不是"自动判对"。

**为什么把它放在第一层**：后面两层都依赖一个稳定的元素集合。
若没有 M1，"实体"是从原始 JSON 现取的，改名/合并/丢弃都无处留痕；
有了 M1，`E1_2`（重复 id 重命名）这类动作才在清单里可见。

## 2. M2 确定性布局与规格探针：没有它，结论无法被复现

**它是什么**：`scripts/layout.py` 是纯函数（无随机、无时间依赖、无环境依赖），
输入 SIR + 配色模板，输出几何模型；`svg_verify.py` 再从几何模型算一个
`spec_sha16 = sha256(画布 + 实体几何 + 关系路径)[:16]`，写进 `verify_report.json.determinism`。
三个渲染后端（手写 SVG / PIL / reportlab）**共享同一个布局模型**。

**没有它会怎样**（同样用下界实现对照）：

| 观测量 | 无 M2（下界实现） | 有 M2（本包） |
|-|-|-|
| 排版方式 | 固定 4 列网格，按数组顺序落格 | 按图类选模板：route 分列 / apparatus 三桶 / flow 链路 |
| 同输入两次的图面 | 网格稳定（因为它足够简陋） | 稳定**且可证**：`figure.svg`/`layout.json` 逐字节一致（4/4 文件，2 轮） |
| 「是不是同一张图」的判据 | 只能肉眼比 | `spec_sha16` 一个 16 位指纹即可对拍 |
| 三个交付件是否一致 | 只有一个 SVG，PNG/PDF 是 0 字节占位 | SVG/PNG/PDF 同源：PNG 尺寸 == 画布×DPI，几何由同一模型导出 |
| 画布溢出 | 元素落到画布外，无人处理 | 等比缩放居中，`canvas.requested` 保留原请求值 |

**边界**：M2 保证的是"**同输入同布局**"，不是"布局一定好看"。
布局质量取决于 `layout.py` 的模板，改模板就会改变所有图的排布——
这是刻意的：模板是**可复用资产**（见 §4 与本文附录 A），不是写死的常数。

**一个容易忽略的副作用**：`evidence.json` 的 sha **不**在确定性承诺内——
它的 `sources[].path` 记的是运行时真实输入路径（取证需要），换目录就会变。
本包把这一条写进 `SKILL.md §8` 与 `TEST.md T3`，就是为了避免有人拿它的 sha 变化
去否定整包的确定性。

## 3. M3 规则资产的机器审计：没有它，语义错误只能靠肉眼

**它是什么**：`assets/connection_rules.json` 把连接语义做成**数据**而不是代码：
合法 `kind` 词表、合法关系词表、以及 8 条规则（如 `sequence` 只能连步骤类、
`connect` 至少一端为结构件、装置图里物料不能作为流向终点、自环非法、回流需复核）。
`scripts/svg_verify.py` 读取该文件逐条审计；**error 级违规强制 `status=partial`**，
warn 级只提示复核（`recycle-review`/`product-terminal`）。

**没有它会怎样**（在一个**预注入 5 类缺陷**的 12 实体 / 13 关系输入上对照）：

| 观测量 | 无 M3（下界实现） | 有 M3（本包） |
|-|-|-|
| 端点不存在的关系 | **照画**：用占位坐标把箭头画出来（外露 1 条） | **丢弃**该关系（外露 0 条；输入 13 → 输出 12） |
| 自环关系 | 照画成一条退化线 | error `no-self-loop`，强制 `partial` |
| `sequence` 连到非步骤实体 | 无从发现 | error `sequence-step-only`，强制 `partial` |
| 违规暴露条数 | **0**（没有审计概念） | **3**（2 error + 1 warn，与注入缺陷对得上） |
| 带缺陷时的状态 | 无 `status` 字段（无法表达"未完成"） | `status=partial` + **退出码 3** +「契约门 G9 失败」 |
| 规则可扩展性 | 无规则可扩展 | 改 JSON 即改审计结论；`--rules` 可换自定义规则集 |

**一个必须说清的对照设计**：为了证明"这 3 条违规是 M3 抓的，不是别处顺带产生的"，
本包跑了第三个条件——**同一份代码，只把 `--rules` 指向一个空对象文件**。
实测该条件的 `figure.svg` 与 `layout.json` 的 sha 与正常运行**完全相同**，
只有 `verify_report.json` 不同（`6ab174447ee34a4a` → `1c04d7a51ba92920`），
违规暴露数从 3 掉到 0。**算法输出不变、审计结论改变** ⇒ 差异只能归因于 M3。

**边界**：M3 审计的是**结构语义**（连接类型、方向、端点存在性、编号连续性、图例一致性），
它**不判断科学正确性**——比如"这个装置该不该接真空泵"取决于方案本身，
本包明确不做这种判断（题面也把科学判断留给原生/LLM 评审）。

## 4. 三者合起来：为什么不是"三个功能的堆叠"

| 若只保留… | 会失去什么 | 后果 |
|-|-|-|
| 只有 M1 | 元素清单有了，但没有几何与审计 | 仍要人读清单、人查连接 —— 回到"有据可查但仍靠人眼" |
| 只有 M2 | 图面稳定了，但元素从哪来、连接对不对无人过问 | 稳定地画出错误结构（**比不稳定更危险**：错误被复现） |
| 只有 M3 | 能发现违规，但没有可比对的元素集合与稳定几何 | 审计对象本身在变，违规结论不可复现 |
| M1+M2+M3 | — | 元素可回溯 → 几何可复现 → 语义可审计；三者互为前提 |

一句话：**M1 让"对不对"可问，M2 让"是不是同一张图"可判，M3 让"错没错"可算。**
缺任何一层，另外两层的结论都无法被第三方独立复核——而题面把"可核验性"单列为评分点。

## 5. 这套机制的可迁移性（机制之外的价值）

三层机制都不绑定"实验装置图"这个题材：

| 机制 | 迁移到其它绘图/文档题需要换掉的 | 不需要换的 |
|-|-|-|
| M1 | 抽取器（`gain_evidence.py` 的解析规则） | `locator`+`quote`+`sha256` 的清单结构 |
| M2 | 布局模板（`layout.py` 的落点规则） | 纯函数约定 + `spec_sha16` 探针 |
| M3 | 规则词表与规则体（`connection_rules.json`） | 规则文件格式 + 审计器 + error⇒降级 的语义 |

具体怎么搬、往哪几个方向搬，见本文附录 A（含 7 类 15 项可复用资产清单与四步复用流程）。

## 6. 这份文件不能证明什么（诚实边界）

- 它**不能**证明本包在平台正式案例上得分更高——正式案例与白板由平台提供，本包不见；
- 它**不能**证明"M1+M2+M3 是唯一正确设计"——它只证明**拿掉这三层后，产物会丢掉
  可回溯性、可复现性与语义审计能力**（三项都有可执行的对照观测）；
- 下界实现 `bare_baseline.py` 是**一个**反例实现，不是"所有既有方案的代表"；
  换一个更聪明的既有方案，差距会缩小——但三层机制各自解决的可观测问题不会消失；
- 对照只跑了 apparatus 图类（route/flow/hybrid 未测），迁移性论断依据的是机制与题材解耦，
  不是实测。

## 2. 四步复用流程

### 第 1 步 · 选层（决定搬哪几层机制）

打开 `references/MECHANISM.md §5` 的迁移表，按你的目标选：

- 只想让产物**可追溯** → 搬 M1（B2 格式 + 你自己的抽取器）；
- 只想让结果**可复现** → 搬 M2（纯函数约定 + B4 探针）；
- 只想让语义错误**被抓住** → 搬 M3（A1 规则格式 + C2 审计器）。

**不要一次搬三层**：三层是串联的，先让一层跑通再叠下一层（本包自己就是先有 M2、
再加 M1、最后加 M3）。

### 第 2 步 · 换数据，不换结构

- 换 `assets/connection_rules.json` 的词表与规则体（A1）；
- 换 `references/vocabulary.md` 的术语（A2）；
- 换 `templates/palette.json` 的配色（A3）。

做完这一步，`scripts/svg_verify.py` 的审计结论就会**自动**跟着变——
这正是"规则做成资产"的意义：**领域知识不埋在代码里**。

### 第 3 步 · 接门禁与自查

1. 把 `scripts/check.py` 的 G 门对着你的新契约改一遍（C1）；
2. 跑一次 `python <scripts>/check.py <你的 result.json>`，确认退出码语义成立
   （0 = 全过 / 1 = 有 issue / 3 = 已产出但未过门）；
3. 把 `references/failure-modes.md` 的 R1–R6 打包门原样抄进你的提交清单（C3）——
   **这一项一行都不用改**，任何走平台预检的包都适用。

### 第 4 步 · 自证增益（把"我更好"变成"可算"）

1. 用 `scripts/bare_baseline.py` 的**思路**写一个你自己领域的下界实现（F3）；
2. 按 `references/GAIN-PROTOCOL.md` 附录 B §0 的三条命令跑 C0/C1/C2；
3. 用 `scripts/gain_probe.py` 的**指标算法**复算 Q1–Q6（D3）；
4. 把结果写成 `D2` 那种机器可读布局，并把**负面结果也写进去**
   （本包写了两条：干净输入上门禁无差异、运行效率无增益）。

## 3. 搬运时的三个陷阱（本包踩过）

| # | 陷阱 | 症状 | 正确做法 |
|-|-|-|-|
| T1 | **把规则写进代码而不是资产** | 换个领域要改代码、还要重新测试 | 规则一律进 `connection_rules.json` 这类数据文件；代码只负责"读规则并执行" |
| T2 | **拿 `evidence.json` 的 sha 当"结果是否一致"的判据** | 换个运行目录 sha 就变（它记的是运行时真实输入路径），误判为"结果不稳定" | 用 `figure.svg`/`layout.json`/`verify_report.json` 对拍，或忽略 `evidence.json` 里的 `path` 字段 |
| T3 | **把 warn 级规则也做成降级** | 全部结果被打成 `partial`，状态失去区分度 | 严守"error 才降级、warn 只提示"；本包 `connection_rules.json` 给每条规则标了 severity，照它执行 |

补充一条**协作陷阱**（本包实测）：把"文档里的字段定义"复制到另一份文档去改，
很容易两边漂移。本包的纪律是——**契约字段只在 `references/OUTPUT_CONTRACT.md` 定义一次**，
其它文档只引用、不改写（见该文件开头的说明）。

- 复用价值排序带主观性（按"省下的工作量"估），你可以按自己场景重排；
- 机制的可迁移性论断依据是"机制与题材解耦"，**不是**实测——本包只在
  apparatus 图类的两个合成案例上跑过对照（见 `references/GAIN-PROTOCOL.md` 附录 B §5）。
