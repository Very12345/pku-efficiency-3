# MECHANISM.md — 本包的独特机制、消融分析与其边界

> 这份文件回答三个问题：**本包相对常规做法多了什么机制**、**去掉它会退化成什么**、
> **怎么验证它真的生效**。所有"退化后果"都尽量给出可机器验证的信号
> （退出码、产物清单、属性计数、sha256），实测值来自 2026-11-22 的运行（详见 `TEST.md`）。
>
> 与 `COMPARE.md` 的关系：原文件已并入本文件 §4（对照口径），避免两处说法不一致。

## 1. 常规做法 vs 本包的机制

| 维度 | 常规做法（通用绘图 / 直接让模型画图） | 本包机制 |
|---|---|---|
| 中间物 | 没有：从文字直接到图 | **声明式机制规格**（实体/边/来源/图例/布局约束）先落盘，图是规格的输出 |
| 类型控制 | 无枚举约束，模型想画什么就画什么 | **raw 规格 schema 门**：枚举外类型直接阻断（不静默归一） |
| 正确性检查 | 靠人眼看 | **双审计**：拓扑审计 + 图例/数据编码审计，产物落盘 |
| 交付形态 | 一张位图/一次导出 | **可编辑分层源 + 逐元素溯源属性**，改一个标签即重导出 |
| 可复现 | 不可判定 | **确定性探针**（布局与 SVG 无时间戳，报 sha16） |
| 结果复核 | 无结构化结果 | **契约化 `result.json`**（信封 + 四形态回显 + 硬性门 + 状态一致性） |

## 2. 逐条机制与消融分析

### M1 规格先行（spec-first）

- **实现**：`scripts/extract.py` 从结构化材料出草稿 → `scripts/model.py` 规范化 → `scripts/layout.py` 读规格布局。
- **没有它会怎样**：图与来源脱钩。具体退化：元件与材料行号失去绑定（无法回答"这条边出自哪一行"）；
  改一个标签必须重画；同一张图的不同导出件（PNG/PDF/SVG）之间可能漂移。
- **可验证信号**：`model.json` 是否存在且含 `entities[]/edges[]/source[]`；
  用 `--model-file` 重跑一次，看三个图件是否同时被重新生成（实测：1 次编辑 + 1 次重跑、3 件全部重生成）。

### M2 raw 规格的 schema 门

- **实现**：`scripts/validate_figure.py:check_schema`，校验对象是**未归一化**的原始规格；
  schema 在 `assets/mechanism-spec.schema.json`。
- **没有它会怎样**：未知类型被规范化阶段静默改写成 `other`。这是最危险的一种退化——
  **错误不会报错，只会被画得很漂亮**：一个本该是"结合"的关系被画成"激活"，图仍然合规、仍然好看。
- **可验证信号**：把某实体 `type` 改成枚举外值（如 `banana`）→ 实测 **exit 3 / failed**，
  只写 `result.json`（14 键），`reason` 说明规格未过门；若实现改成"先归一化再校验"，这个用例会变成 exit 0。

### M3 双审计闭环

- **实现**：`scripts/topology.py`（P01–P08：id/端点/方向/同名消歧/重复边/自环/反馈/区室词表）
  + `scripts/legend_audit.py`（L01–L08、E01–E02：图例覆盖、箭头=图例、颜色⊆图例∪映射、
  虚线语义、线宽映射、图层命名、数值溯源、色带端点）。
- **没有它会怎样**：图例与图面不一致、上下游颠倒、数值无来源这三类错误只能靠人眼，
  而它们恰恰是"看起来很专业"的错误。
- **可验证信号**：两个审计产物是否落盘；对**没有这套机制的产物**执行同一条命令 →
  实测 `validate_figure.py` exit 1（`ok=False`）；对本包产物 exit 0（30 项、fails=0）。

### M4 可编辑分层源 + 逐元素溯源

- **实现**：`scripts/pathway_svg.py` 输出 7 个 `layer-*` 组
  （compartment / edge / entity / label / title / legend / meta），
  元素带 `data-id / data-type / data-source / data-from / data-to / data-evidence`。
- **没有它会怎样**：只能交一张位图。退化是可量化的：图层组 0、`data-source` 0、
  标签只能靠全文搜索定位（`data-id` = 0）——**"可编辑交付"与"来源可追溯"同时消失**。
- **可验证信号**：SVG 里具名图层数与 `data-source` 计数（实测本包 7 层 / 18 个溯源属性；
  §4 的基础形态两项均为 0）。

### M5 确定性探针

- **实现**：布局与 SVG 生成不含时间戳；`result.json.self_check.determinism` 报
  `model_sha16` / `svg_sha16`。
- **没有它会怎样**：无法判断"评审看到的图"与"提交的图"是否同一张；任何"重跑一次看看"的
  核对都失去意义。
- **可验证信号**：同输入双跑比对 sha256 —— 实测 SVG/PNG/model/topology/legend_audit **逐字节一致**，
  PDF 仅因 matplotlib 内嵌 `CreationDate` 不同（已如实声明为非确定性项）。

### M6 契约化终态

- **实现**：`scripts/result_writer.py` 写信封 + 四形态回显；`scripts/check_contract.py` 独立复查；
  硬性门 G1–G8；`status` / 退出码 / `gates` 三元组一致性。
- **没有它会怎样**：结果无法被机器复核——评审判"没找到完整解"，人也无法复算；
  成功与失败在产物上没有区别（都只有几张图）。
- **可验证信号**：信封 19/19、顶层 null 0、gates 8/8、exit 0；对无契约的产物同命令 exit 1。

## 3. 机制之间的依赖链（断链会怎样）

```
M1 规格 ──▶ M2 门 ──▶ M4 渲染/溯源 ──▶ M3 审计 ──▶ M6 契约
                └────────▶ M5 确定性探针（覆盖 M1/M4 两段）
```

- **断 M1**：M3 没有审计对象（图不可审），M5 没有可比对的中间物，M6 只能写空信封。
- **断 M2**：M3/M4 会把错误断言渲染得非常专业（最隐蔽的一种失效）。
- **断 M4**：M3 的图例/编码审计失去载体（没有 `data-*` 可读），"可编辑"承诺落空。
- **断 M3**：M6 的 gates G6/G7 无从判定，`success` 变成自我声明。
- **断 M5**：一切"重跑核对"退化为相信口头描述。
- **断 M6**：前面五条机制的产物无法被打分与复核，整条链的价值无法交付。

## 4. 与基础形态的对照口径

对照条件、判据与实测读数已系统化在 `references/GAIN-PROTOCOL.md`（本包不重复维护两套口径）；
此处只保留与本文件相关的**机制级结论**：

| 机制 | 基础形态实测 | 本包实测 |
|---|---|---|
| M4 分层与溯源 | 图层 0、`data-source` 0、`data-id` 0 | 7 层、18 个溯源属性、元素可按 id 定位 |
| M3 审计 | 同两条命令 exit 1（无契约、`ok=False`） | exit 0 / exit 0（30 项） |
| M6 契约 | 无 `result.json`（信封 0/19） | 19/19、null 0、gates 8/8 |
| M2 门 | 无类型约束概念 | 枚举外类型 → exit 3 |
| M1/M5 | 无规格、无确定性口径 | 规格可重导出；双跑 5/6 文件逐字节一致 |

平台侧的真实对照（基础条件 vs 加载 Skill，每条件 3 次重复）由平台运行；
本包只提供判据与可复算命令，不预测、不引用任何分数。

## 5. 边界（这些机制**不**解决什么）

1. **科学性上限**：一条关系究竟该判 activation 还是 binding，最终仍需人/模型评审；
   M2 只能保证"不出现枚举外类型"，不能保证"类型判对了"。
2. **图面美观**：布局是确定性规则布局，不追求排版艺术；本包不为美观度作任何承诺。
3. **散文材料自动化**：M1 对散文/PDF 依赖人工抽取（CP3 强制核验），这是"准确率优先"的取舍。
4. **跨领域迁移**：机制链可迁移（见 `ASSET-INDEX.md`），但**类型枚举与配色必须重新定义**，
   直接照搬生物语义到别的领域会制造新的错误。
5. **平台评分**：本包不运行、不预测平台对照实验与分数。
