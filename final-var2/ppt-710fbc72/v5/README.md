# Academic Slide Adapter —— 多案例泛化与题集包（v5）

**一句话定位**：这是一个**多案例泛化与题集包**。它在基线（一个示例案例的两阶段流程）之上，
新增**两个不同题材的合成案例**（L1 结构完整 / L2 退化输入）与 `references/CASE-SET.md`，
并新增 `scripts/run_case_set.py`，把「泛化」从一句形容词变成**可测量的区间对拍**：
每个案例的期望区间**事先写在清单里**，跑完由脚本逐项测量、逐项判定，
不一致就报 `RANGE-MISS`，**不会静默算作通过**。

> 三个案例都是**合成示意案例**（`_meta` 与材料首行都写明「非真实研究结果」）。
> 题集回答的问题是「换个题材、换个页预算、换成退化输入，还能不能跑」，
> 不是「讲得好不好」，也不是平台分数。

## 1. 依赖与环境

| 项 | 值 |
|-|-|
| 运行时依赖 | **python-pptx**、**Pillow**（numpy / matplotlib 仅用于版本记录） |
| 实测 Python | **3.13.9** |
| 实测系统 | **Windows 11 + Git Bash（MSYS2）** |
| 预览 | 本机**无 LibreOffice / PowerPoint** ⇒ 预览为 **PIL 示意图**，如实标注，不冒充像素级导出 |
| 题集规模 | **3 个案例**（1 个自带示例 + 2 个新增）；三案各自独立子进程 |

`scripts/run_case_set.py` 只用标准库（`argparse / json / os / shutil / subprocess /
sys / time`），不引入新依赖。

**一条容易踩的坑**：三案目录里**没有** `figs/*.png`。这不是遗漏，是题面硬约束
（Skill 资源只允许 UTF-8 文本，≤50 个文件 / 单个 ≤500KB / 合计 ≤2MB）。
所以脚本的做法是：**先把案例复制到包外**，再现场合成占位图
（`make_synthetic_inputs.py --out-dir <副本>/figs`），然后才跑主流程。
这样既满足硬门，又不会在包里留下 `.pyc` 或图片。

## 2. 快速上手：在**包外**副本上跑题集

```bash
SKILL_DIR=<本包根目录>            # 平台装到 /skills/weekly-skill
RUN=<任意可写临时目录>

cp -r "$SKILL_DIR" "$RUN/pkg"
python "$RUN/pkg/scripts/run_case_set.py" --skill "$RUN/pkg" \
    --cases "$RUN/pkg/examples" --run "$RUN/caseset" \
    --json "$RUN/caseset.json" --markdown "$RUN/caseset.md"
# 实测：3 个案例 / 0 个超出声明区间 / 1 个已声明边界命中 / 退出码 0
```

两个输出文件是**同一次测量**的两种形态：`--json` 给机器读，`--markdown` 给人读。
**声明与判定同源**：区间写在 `examples/cases/case_manifest.json`，测量由
`run_case_set.py` 完成；两者不一致时报 `RANGE-MISS`（并指出是哪个字段），
不会静默算作通过。

### 2.1 只跑某个案例

```bash
# 先列出题集里的案例
python "$RUN/pkg/scripts/run_case_set.py" --list --cases "$RUN/pkg/examples"

# 只跑 L2 那一案（逗号分隔，不要空格）
python "$RUN/pkg/scripts/run_case_set.py" --skill "$RUN/pkg" \
    --cases "$RUN/pkg/examples" --run "$RUN/only-c" \
    --only case-c-uhi-remote-302
```

| 参数 | 作用 |
|-|-|
| `--list` | 列出案例 id 后退出，不跑任何东西 |
| `--only <id,id>` | 只跑指定案例 |
| `--cases <dir>` | 题集所在目录（`examples`，内含 `cases/case_manifest.json`） |
| `--run <dir>` | 包外暂存目录（**不要在包内**） |
| `--json` / `--markdown` | 报告落盘路径 |
| `--timeout <s>` | 单案例超时（默认 300 秒） |

**退出码语义**：`0` = 每个案例都在声明区间内；`1` = 至少一个 `RANGE-MISS` 或崩溃；
`2` = 用法/环境错误。

### 2.2 单案例的观测点

判断一案的产出是否可用，看这六项（顺序即优先级）：

1. `exit` 与 `status`；
2. `slide_count` —— 页数**是否命中声明值/区间**（页计划是确定性纯函数）；
3. `notes_frac` —— 逐页讲稿覆盖率；
4. `evidence_loc_frac` —— 页级主张**带 `文件:行`** 的比例；
5. `figures_placed_frac` + `contract_gates_pass` / `contract_gates_failed`；
6. `null_top_keys` —— 契约禁止 `null` 占位，这里必须是 0。

## 3. 题集三案

| # | case_id | 难度层 | 题材 | 页预算 / 时长 | 图 | 表 | 结构化字段完整度 |
|-|-|-|-|-|-|-|-|
| A | `example-catalyst-201` | **L0** 基线接口 | 催化化学（Cu-ZnO/γ-Al₂O₃ 双金属催化剂，CO₂ 加氢制甲醇） | 10 页 / 12 min | 2 | 1 | 完整（manifest: `complete`） |
| B | `case-b-gnn-potential-301` | **L1** 结构完整 | 计算材料（图神经网络势函数 + 固态电解质 Li₆PS₅Cl 的锂离子输运 MD） | 12 页 / 15 min | 2 | 1 | 完整；39 条来源定位全部形如 `material.md:N` |
| C | `case-c-uhi-remote-302` | **L2** 退化输入 | 城市环境遥感（Landsat 9 + Sentinel-2 地表温度反演与城市热岛归因） | 9 页 / 10 min | 1 | 1 | **只给最小 12 键**；研究问题/方法/结果/讨论/局限/结论六个故事线字段全部缺席 |

**为什么这么分层**：L0 问「接口对不对」，L1 问「换个题材还行不行」，
L2 问「输入烂了还行不行」。三层走的是**不同的代码路径** ——
L2 命中的是 `extract.py` 的 `supplemented_from_material` 补位分支，
**L0 永远走不到它**，所以「L0 通过」在逻辑上**推不出**「L2 通过」。
这正是要放三个案例而不是一个的原因。

| 判据 | A | B | C |
|-|-|-|-|
| `main.py` 退出码 | **0** | **0** | **0** |
| `status` | `success` | `partial` | `partial` |
| `slide_count` | **10**（声明 10） | **13**（声明区间 [12, 13]） | **9**（声明 9） |
| 讲稿覆盖 `notes_frac` | 10/10 = **1.0** | 13/13 = **1.0** | 9/9 = **1.0** |
| 证据定位覆盖 `evidence_loc_frac` | 13/13 = **1.0** | 26/26 = **1.0** | 34/34 = **1.0** |
| 图表落位 | 2/2 = **1.0** | 2/2 = **1.0** | 1/1 = **1.0** |
| 含表页数 | 2 页 | 2 页 | 1 页 |

| 顶层 `null` 键 | **0** | **0** | **0** |
| 方案套用 | 10/10，偏差 **0** | 13/13，偏差 **0** | 9/9，偏差 **0** |
| `uncertainty` 条数 | 1 | 2 | 3 |
| **判定** | **in-range** | **boundary-hit**（已声明） | **in-range** |

三案的**共同点**值得单独指出：`evidence_loc_frac` 全部 **1.0**、契约门全部 **8/8**、

也就是说，**换题材（催化 → 计算材料 → 遥感）、换页预算（10 → 12 → 9 页）、
换输入完整度（完整 → 最小字段）之后，契约层与证据层没有退化**。
退化只出现在 §5 列出的两处，而且两处**都被审计抓到了**（不是没发现）。

## 5. 泛化边界（实测，必读）

以下三条是本次题集最有价值的产出：**全是实测暴露出来的边界，全部可复现、全部有数字。**
完整根因与复现命令见 `references/CASE-SET.md` **§4**。

### ① 页预算会被「带媒体的结果条目数」顶破：声明 12，实测 13

案例 B 声明 12 页，实测 **13** 页（`planned_slides=13`），`status` 因此降为 `partial`。
根因是它的 7 条 `results` **各自都引用了图或表**，触发「每条带媒体的结果各占一页」分支
⇒ 结果页 7 张；而确定性裁剪是一次性三步（合并讨论+局限 → 删议程 → 合并末两页结果），
**最多只能回收 3 页**，不够用。
⇒ 清单因此把 B 的页数写成区间 **[12, 13]** 并附上这段理由，由脚本判为 `boundary-hit`
（**不是** `in-range`，也**不是**静默通过）。**上限 13 是实测值，不是设计目标。**

### ② 「只有表格、没有图」的结果页会丢掉它自己的主张条目

案例 B 第 8 页（只放表 1）在幻灯片上只有标题、表题行与页脚，
计划里的主张条目**没有出现在页面上**；对照第 9 页（同时有图和表）主张正常写出。
检出方式是 `audit.py` 的 `content.claim_coverage` 检查（逐页抽取主张前 18 个字符做字面匹配），
它把这一条报成 `warn`，`status` 随之降为 `partial`。
⇒ 这是**已检出、已降级、未修复**的行为：要么给「只有表」的结果条目补一条图引用，
要么接受 `partial` + 这条 warn。

### ③ 一页塞太多主张时，末尾的主张会被文本框装不下而丢掉

案例 C 第 4 页把 **6 条**主张分到同一页（它们都不带媒体引用，被归到同一个收集页），
页面上实际写到第 4 条末尾就断了，**第 5、6 条没有出现**。
字号阶梯只负责把字号压到 12pt 为止；**压到地板仍装不下时，本包的策略是「只报告、不继续压」** ——
把字压到不可读比少写一条主张更糟。这条取舍是有意的，代价就是这里看到的丢条。
⇒ 规避方式：给这类页面的主张数量设上限（案例作者控制），或者接受 warn + `partial`。

### ④ 题集**没有**覆盖的东西（别把这三案当成泛化的全部证据）

- **没有跨模板族**：三案的模板链全部落到运行时生成的内置回退模板（`opened_from=builtin`）。
  多母版、多主题、商业模板族、SmartArt **全部没测**。
- **没有真 PDF / 像素级导出一致性**：本机无 LibreOffice / PowerPoint，预览是 PIL 示意图，
  因此只测到「有/无有效预览」，**测不到像素级差异**。
- **没有中文以外的语言**：三案 `language` 都是 `zh`，`en` 分支未跑。
- **没有起始 deck 编辑场景**：三案都没给 `starting_deck`，
  所以 `change_records[].action=edit_starting_deck` 与「旧页连关系一起移除」这条路径
  在本题集里**未被覆盖**。
- **没有超长材料**：三案材料都在 51–52 行量级，**没有**测过上百行的长材料。
- **没有多图并排**：每页最多 2 张图（案例 B 第 9 页），没有测过 3 张以上并排。

## 6. 限制，以及题集**不能**用来做什么

| 不能当作 | 原因 |
|-|-|
| **平台正式案例 / 白板** | 组织方的固定案例与对照由平台提供或生成；本包**不预置白板、不冒充成绩** |
| **分数预测** | 这里的 `in-range` / `boundary-hit` 是本包**自己声明**的区间，与平台评分无关 |
| **「质量更好」的证明** | 题集只回答「**能不能跑、跑出来是什么形状**」，不回答「讲得好不好」；质量对照口径另见 `references/GAIN-PROTOCOL.md` |
| **真实研究结果的来源** | 三案均为合成示意案例，材料与数值**不是**真实研究数据 |

另有三条**方法学限制**：

1. `status=partial` 在 L1/L2 上**不一定是缺陷** —— L2 的表格无 `rows` ⇒ 必然有 warn，
   `partial` 在那里是**正确**结果。判断要看 `uncertainty` 与审计条目，而不是只看状态字。
2. 区间是**下限式**判据（覆盖率取最小值、页数取精确值或区间），
   所以「通过区间」**不等于**「达到最优」。
3. 题集**不是性能基准**：三案各跑一次约 1.5 秒，样本量小，不能用于吞吐量结论。

## 7. 维护：新增一个案例

**四步，一步都不能省**（完整约定见 `references/CASE-SET.md` §5）：

1. 在 `examples/cases/<case-dir>/` 放 `case.json` / `task.md` / `material.md`；
2. 在 `examples/cases/case_manifest.json` 加一条，写清**难度层**、**期望产出结构**、
   **可接受区间**与**这案在考什么** —— 区间必须**先声明**，否则测量就没有判据；
3. **真跑一次** `run_case_set.py`，把实测数字补进 `references/CASE-SET.md` §2；
4. 若发现新的失效方式，追加进 §4 并写明根因 ——
   **不要把区间改宽来掩盖实测**；要改区间，必须像 §4.1 那样附上可复现的理由与实测上限。

### 格式红线（踩了会**静默抽不到东西**，最难查）

- 图/表标题行必须写成 **`图1：…` / `表1：…`**（图号后紧跟**中文全角冒号**）；
  `图1 催化剂…`（用空格分隔）**匹配不上** `extract.py` 的标题正则。
- 材料**小节标题**必须含 `extract.py` 的分桶关键词：
  背景/问题/引言、方法/实验、结果/数据/图/表、讨论、限制/局限/不足、结论/总结。
- 小节内的编号**不要**写成 `2.1 xxx` 形式（会被误判成小节标题并清空分桶），
  用 `（1）` 这类中文括号编号。
