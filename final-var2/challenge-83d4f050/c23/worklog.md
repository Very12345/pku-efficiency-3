## 2. 为什么把"机制"写成"没有它会怎样"

**"新机制"若说不出退化后果，就无法与"多写了一个脚本"区分开。** 因此每条机制都配消融式论证，
并尽量给出可机器验证的信号：

| 机制 | 没有它会怎样（可验证） |
|---|---|
| M1 规格先行 | 图与来源脱钩：元件无法回溯材料行号；改标签要重画；导出件漂移 |
| M2 raw schema 门 | 未知类型被静默改写 → 错误论断被"画得很专业"（实测把校验点放在 raw 规格上时，枚举外类型 → exit 3） |
| M3 双审计 | 图例/方向/溯源错误只能靠人眼（实测：对无机制产物同命令 exit 1，对本包 exit 0） |
| M4 分层 + 溯源 | 只能交位图（实测：图层 0、`data-source` 0、`data-id` 0） |
| M5 确定性探针 | 无法判定"评审看到的图"与"提交的图"是否同一张（实测：双跑 5/6 文件逐字节一致） |
| M6 契约化终态 | 结果无法被机器复核（实测：无契约产物信封 0/19、`check_contract.py` exit 1） |

**边界也写清楚了**（避免把机制说成万能）：机制保证"类型不越界、结构可审计、产物可编辑可复现、
结果可复核"，**不保证**科学判断的最终正确性与美观度。

## 3. 为什么把"复用"写成清单 + 步骤

- 只给"可复用"三个字没有意义；复用者需要知道**搬哪一个文件、依赖是什么、搬之前必须替换什么**。
  因此资产表每行都有"复用前必须替换"列（例如 A2 调色板必须换颜色值、类型→形状映射、
  证据→线宽档位；A7 流水线必须换区室定义与布局带规则）。
- 只给清单也不够：复用真正容易断在三处（枚举/配色/语义表没同步、只搬渲染不搬审计、
  把示例数据搬进正式输出）。因此给出**命令级三步 + 适配检查表 + 五条常见坑**，
  并明确"第 4 条故意失败用例必须返回 exit 3，否则说明门被绕过"。
- 明确写出**不建议照搬的东西**：示例数据、本机运行痕迹（sha256/路径/时间戳）、平台分数。

## 4. 缺陷修复：`--materials-dir` 崩溃（唯一触碰脚本的一处）

**修复前**（基线版，包外临时目录副本实测）：`exit 1`，
`TypeError: _path_normpath: path should be string, bytes or os.PathLike, not list`，无产物。
**根因**：该选项用 argparse `action="append"`（list），`collect_material_paths()` 按 list 迭代，
而 `resolve_paths()` 按 str 处理——同一参数两处类型约定不一致。
**修复**：入参归一化（list/tuple/str 都接受；str 仍按 `os.pathsep` 拆分）；
不改参数名、默认值、退出码语义与算法/产物格式。
**修复后**：`exit 0`、`status=success`、`gates 8/8`、7 件产物。
（该修复已写入 `ASSET-INDEX.md` §5 第 1 条"复用时的常见坑"。）
