## 1. 实际效果（40）

**任务完成度（15）**：4 个案例全部真跑通过，覆盖三种图类与三个难度层：

| 难度层 | 案例 | 图类 | 规模 | 考什么 |
|-|-|-|-|-|
| 低 | `demo-biotech-route-01` | route | 10 / 9 | 线性主链、阶段分列 |
| 低 | `apparatus-spec-01` | apparatus | 6 / 5 | 三桶布局、物料不作终点 |
| 中 | `mbr-wastewater-flow-01` | flow | 14 / 14 | 分流/合流/回流/废料出口/出水两路 |
| 高 | `dtms-stage-route-01` | route | 18 / 18 | 4 阶段 + 2 里程碑 + 依赖方向 + 返工回流 + 编号对照 |

每次运行产出 7 件（`evidence/layout/figure.svg/figure.png/figure.pdf/verify_report/result.json`），
覆盖题面六类要素（科学实体 / 空间关系 / 数据编码 / 图例标注 / 可编辑源文件 / 导出格式）。

**结果正确性（15）**：正确性由三道机器门保证（证据门 CP1、连接门 CP2、契约门 CP4），
并且**用期望表把它变成可判的**：`references/case-set.json` 对每案给出
`status` / 实体关系区间 / `verify_ok` / `allowed_warnings` / `forbidden_errors`。
关键设计：期望写成**区间 + 不变量**，所以"按材料补一条真实连接"不会被误判 FAIL，
而"少一条回流 / 少一个终点 / 方向反了"会被 `forbidden_errors` 抓到。
判据"能判错"的证据在 `TEST.md` T4（把下限改成 30 ⇒ 该案 FAIL、退出码 1）。

**结果完整性（5）**：`result.json` 顶层 18 个字段、`output_contract` 四段齐全；
`status` 与退出码配合使用；**告警 ≠ 失败**（C-1/C-2 各 1 条 `recycle-review`，
`status` 仍 `success`，这是"回流需人工复核"的设计行为）。

**结果可核验性（5）**：每案留下 `evidence.json`（逐条 `locator`+`quote` + 材料 `sha256`）、
`layout.json`（几何中间证据）、`verify_report.json`（含 `spec_sha16` 确定性探针）。
四案的 `spec_sha16` 实测值记录在 `CASE-SET.md §5`，可跨机器对拍。

## 2. 使用增益（25）

**质量增益（15）**：对照的不是"裸 Agent"，而是**没有题集时的自己**：

| | 没有题集 | 有题集 |
|-|-|-|
| 换题材后"还能不能用" | 只能靠印象和零散试跑 | 一句 `case_set_run.py` 给 PASS/FAIL 与偏差明细 |
| "回流丢了没有" | 人眼看图 | `forbidden_errors` / `warnings` 里直接体现 |
| "这个题材要不要结构化输入" | 事后返工才明白 | `--text-only` 一跑就知道保留率 |

**效率增益（5）**：本包**不声称**出图更快（绘图耗时由布局与渲染决定，与题集无关）。
可站得住的效率增益只有一条：**验收从"逐案手工跑 + 人眼比对"变成一条命令**。
不写倍数——没有做对照计时，写倍数就是不诚实。

**增益可验证性（5）**：全部由 `case_set_run.py` 现场复算：跑批一次得到
`cases/passed/failed/without_expectation` 四个计数与逐案偏差列表；
`--text-only` 再给出每案的实体/关系保留率。任何人可在自己机器上重跑。

## 3. 创新增益（15）

**新增能力（5）**：`scripts/case_set_run.py` —— 题集跑批与泛化度测量。
它不只是"批量执行"，而是把**期望结构**（区间 + 不变量 + 允许告警）变成机器判据，
并对"未登记的案例"给出 `NO-EXPECTATION` 提醒（防止案例加了却没验收）。

**方法改进（5）**：把"泛化边界"从形容词变成数字。`--text-only` 的构造很简单
（只留 `text` 字段，其余删掉），但它一次性回答了三个问题：文本解构能保住多少、
哪些规则告警会在退化后消失、**退化是否会自动触发状态降级**（实测：不一定会）。

**创新证据（5）**：实测数据在 `CASE-SET.md §6`：实体保留率 0.200–0.667、
关系保留率 **0.000**–0.357；装置图（C-4）5 条关系全丢 + 4 个孤实体 ⇒ `status`
由 `success` 掉到 `partial`；而 C-3 只剩 2 实体 1 关系仍报 `success`。
**这三条都是"如果不测就写不出来"的结论。**

## 4. 可靠体验（10）

**调用与易用性（3）**：案例目录遵循平台的 `/input` 约定（`case.json` + 同目录 `task.md`），
所以 `--case <案例目录>` 一条命令即可；跑批、单案、自查三个动作各有独立入口与退出码。

**运行稳定性（4）**：8 次运行（4 案结构化 + 4 案文本探针）**全部正常结束**，
其中结构化 4/4 `verify.ok=true`、G1–G10 全过；文本探针 1 案降级 `partial`（预期内）、
其余 3 案 `success` 且各带 `uncertainty[scope=relations]` —— 状态与证据一致，没有撒谎的 case。

**异常处理（3）**：`references/failure-modes.md` 给出"现象 → 根因 → 处置 → 规则号"；
SKILL.md 保留 D1–D12 并新增 **D13**（加了案例没登记 = 没验收）、**D14**（区间太松时
把不变量翻译成 `forbidden_errors`）。这两条针对的都是本题集特有的维护风险。

## 5. 生态贡献（10）

**文档完整性（3）**：SKILL / README / TEST + 7 份 references（契约 / RUBRIC /
题集 / 题集期望表 / 失败模式 / 术语表 / 布局蓝图），案例自带 `task.md` 说明材料来源。

**资源可复用性（4）** —— "拿走即用"清单：

| 资产 | 复用到别的题要改什么 |
|-|-|
| `references/case-set.json` 的**字段布局** | 换 `case_path` 与期望区间即可；字段结构（区间 + 允许告警 + 禁止规则 + 不变量）任何绘图/文档题都适用 |
| `scripts/case_set_run.py` 的**跑批骨架** | 换 `_observe` 里抽取的字段；sandbox/比对/泛化探针三段逻辑不动 |
| `examples/cases/<案>/{case.json,task.md}` | 复制两个文件即成一个新案例（`CASE-SET.md §7` 三步流程） |
| `--text-only` 泛化探针 | **与题材无关**：任何"结构化输入 → 产物"的 Skill 都能用同一手法量化退化 |
| `assets/connection_rules.json` + `templates/palette.json` | 换数据即换行为，不改代码 |
| `references/failure-modes.md §8`（R1–R6 打包门） | **一行都不用改**，任何走平台预检的包都适用 |

**分享推广价值（3）**：本版沉淀的是一套**可复用的"多案例验收"方法**：
案例（输入）+ 期望（判据）+ 跑批（执行）+ 泛化探针（边界）四件套。
它回答了"一个 Skill 到底能不能换题材用"这个每个绘图类作品都会遇到的问题，
而且成本只有几秒钟。
