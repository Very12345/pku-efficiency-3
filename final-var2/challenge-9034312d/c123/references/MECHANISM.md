# MECHANISM.md — 本包的三层独特机制（含"没有它会怎样"）

> 这份文件回答创新增益里最难自证的一条：*"是否证明创新点相对已有方案的边界与价值"*。
> 写法刻意反过来：**先说清"拿掉它会怎样"，再说它是什么**。
> 每一节的"没有它"都不是设想，而是有一份**可执行的反例实现**对照过：
> `scripts/bare_baseline.py` 就是"三个机制全被拿掉"的那一侧，
> 逐项数字见 `references/COMPARISON-SUMMARY.md`（本包内附，含命令）。
>
> 为什么用这种方式自证：如果只说"我做了 SIR + 确定性布图 + 规则资产"，读者无法判断
> 这些设计是必要还是装饰。把"拿掉后的产物"摆出来，边界就变成可检查的事实。

## 0. 三层机制速览

| # | 机制 | 一句话 | 没有它会怎样（可观测） |
|-|-|-|-|
| M1 | **证据中间层**（evidence-first） | 图面元素在进入渲染之前，先落成一份带 `locator`+`quote`+材料 `sha256` 的清单 | 元素只剩名称，无法回答"这个盒子出自材料哪一句" |
| M2 | **确定性布局与规格探针** | 布局是纯函数；`spec_sha16` 把"同输入 ⇒ 同布局"变成可对拍的指纹 | 同输入两次可能给出不同图面，结论无法被别人复现 |
| M3 | **规则资产的机器审计** | 连接语义做成**可编辑的 JSON 资产**，由 `svg_verify.py` 逐条审计，error 级强制降级 | 连接错、方向反、编号断都只能靠肉眼；且规则无法被第三方扩展 |

三者是**串联**关系，不是三个并列功能：M1 产出可比对的元素集合 → M2 把它变成确定的几何
→ M3 在几何之上审计语义。所以下面的对照也是按这个顺序做的。

## 1. M1 证据中间层：没有它，图面就无法回溯

**它是什么**：`scripts/gain_evidence.py` 在布图之前先跑一遍，产出 `evidence.json`：
每条实体/关系一个 `{id, type, ref, locator, quote}`；同时给每个输入文件记
`sha256`/`size`/`role`。这份清单回显进 `result.json.evidence`，
后续 `data_mapping` 与 `element_traceability` 都从它派生。

**没有它会怎样**（用 `bare_baseline.py` 对照，同一份 8 实体 / 7 关系输入）：

| 观测量 | 无 M1（下界实现） | 有 M1（本包） |
|-|-|-|
| 图面元素的出处信息 | 只有 `<text>` 里的名称 | 每元素一条 `locator`（材料章节）+ `quote`（原文片段） |
| 来源绑定率（有 `locator` 的元素 ÷ 元素总数） | **0.00**（产物里没有这个字段） | **1.00** |
| 「用的是哪一版材料」 | 无从回答 | `evidence.source_files[].sha256` 直接给出 |
| 元素 ↔ 材料双向回溯 | 不可能 | `element_traceability[]` + `evidence.items[].ref` 互指 |

**边界（它做不到什么）**：M1 只保证"出处字段存在且指向真实读到的文件"；
它**不判断**引文是否贴切（那需要人读），也**不阻止**一条断头关系被写进材料
（断头由 M3 处理）。所以 M1 的价值是"让复核成为可能"，不是"自动判对"。

**为什么把它放在第一层**：后面两层都依赖一个稳定的元素集合。
若没有 M1，"实体"是从原始 JSON 现取的，改名/合并/丢弃都无处留痕；
有了 M1，`E1_2`（重复 id 重命名）这类动作才在清单里可见。

## 2. M2 确定性布局与规格探针：没有它，结论无法被复现

**它是什么**：`scripts/layout.py` 是纯函数（无随机、无时间依赖、无环境依赖），
输入 SIR + 配色模板，输出几何模型；`svg_verify.py` 再从几何模型算一个
`spec_sha16 = sha256(画布 + 实体几何 + 关系路径)[:16]`，写进 `verify_report.json.determinism`。
三个渲染后端（手写 SVG / PIL / reportlab）**共享同一个布局模型**。

**没有它会怎样**（同样用下界实现对照）：

| 观测量 | 无 M2（下界实现） | 有 M2（本包） |
|-|-|-|
| 排版方式 | 固定 4 列网格，按数组顺序落格 | 按图类选模板：route 分列 / apparatus 三桶 / flow 链路 |
| 同输入两次的图面 | 网格稳定（因为它足够简陋） | 稳定**且可证**：`figure.svg`/`layout.json` 逐字节一致（4/4 文件，2 轮） |
| 「是不是同一张图」的判据 | 只能肉眼比 | `spec_sha16` 一个 16 位指纹即可对拍 |
| 三个交付件是否一致 | 只有一个 SVG，PNG/PDF 是 0 字节占位 | SVG/PNG/PDF 同源：PNG 尺寸 == 画布×DPI，几何由同一模型导出 |
| 画布溢出 | 元素落到画布外，无人处理 | 等比缩放居中，`canvas.requested` 保留原请求值 |

**边界**：M2 保证的是"**同输入同布局**"，不是"布局一定好看"。
布局质量取决于 `layout.py` 的模板，改模板就会改变所有图的排布——
这是刻意的：模板是**可复用资产**（见 §4 与 `REUSE-GUIDE.md`），不是写死的常数。

**一个容易忽略的副作用**：`evidence.json` 的 sha **不**在确定性承诺内——
它的 `sources[].path` 记的是运行时真实输入路径（取证需要），换目录就会变。
本包把这一条写进 `SKILL.md §8` 与 `TEST.md T3`，就是为了避免有人拿它的 sha 变化
去否定整包的确定性。

## 3. M3 规则资产的机器审计：没有它，语义错误只能靠肉眼

**它是什么**：`assets/connection_rules.json` 把连接语义做成**数据**而不是代码：
合法 `kind` 词表、合法关系词表、以及 8 条规则（如 `sequence` 只能连步骤类、
`connect` 至少一端为结构件、装置图里物料不能作为流向终点、自环非法、回流需复核）。
`scripts/svg_verify.py` 读取该文件逐条审计；**error 级违规强制 `status=partial`**，
warn 级只提示复核（`recycle-review`/`product-terminal`）。

**没有它会怎样**（在一个**预注入 5 类缺陷**的 12 实体 / 13 关系输入上对照）：

| 观测量 | 无 M3（下界实现） | 有 M3（本包） |
|-|-|-|
| 端点不存在的关系 | **照画**：用占位坐标把箭头画出来（外露 1 条） | **丢弃**该关系（外露 0 条；输入 13 → 输出 12） |
| 自环关系 | 照画成一条退化线 | error `no-self-loop`，强制 `partial` |
| `sequence` 连到非步骤实体 | 无从发现 | error `sequence-step-only`，强制 `partial` |
| 违规暴露条数 | **0**（没有审计概念） | **3**（2 error + 1 warn，与注入缺陷对得上） |
| 带缺陷时的状态 | 无 `status` 字段（无法表达"未完成"） | `status=partial` + **退出码 3** +「契约门 G9 失败」 |
| 规则可扩展性 | 无规则可扩展 | 改 JSON 即改审计结论；`--rules` 可换自定义规则集 |

**一个必须说清的对照设计**：为了证明"这 3 条违规是 M3 抓的，不是别处顺带产生的"，
本包跑了第三个条件——**同一份代码，只把 `--rules` 指向一个空对象文件**。
实测该条件的 `figure.svg` 与 `layout.json` 的 sha 与正常运行**完全相同**，
只有 `verify_report.json` 不同（`6ab174447ee34a4a` → `1c04d7a51ba92920`），
违规暴露数从 3 掉到 0。**算法输出不变、审计结论改变** ⇒ 差异只能归因于 M3。

**边界**：M3 审计的是**结构语义**（连接类型、方向、端点存在性、编号连续性、图例一致性），
它**不判断科学正确性**——比如"这个装置该不该接真空泵"取决于方案本身，
本包明确不做这种判断（题面也把科学判断留给原生/LLM 评审）。

## 4. 三者合起来：为什么不是"三个功能的堆叠"

| 若只保留… | 会失去什么 | 后果 |
|-|-|-|
| 只有 M1 | 元素清单有了，但没有几何与审计 | 仍要人读清单、人查连接 —— 回到"有据可查但仍靠人眼" |
| 只有 M2 | 图面稳定了，但元素从哪来、连接对不对无人过问 | 稳定地画出错误结构（**比不稳定更危险**：错误被复现） |
| 只有 M3 | 能发现违规，但没有可比对的元素集合与稳定几何 | 审计对象本身在变，违规结论不可复现 |
| M1+M2+M3 | — | 元素可回溯 → 几何可复现 → 语义可审计；三者互为前提 |

一句话：**M1 让"对不对"可问，M2 让"是不是同一张图"可判，M3 让"错没错"可算。**
缺任何一层，另外两层的结论都无法被第三方独立复核——而题面把"可核验性"单列为评分点。

## 5. 这套机制的可迁移性（机制之外的价值）

三层机制都不绑定"实验装置图"这个题材：

| 机制 | 迁移到其它绘图/文档题需要换掉的 | 不需要换的 |
|-|-|-|
| M1 | 抽取器（`gain_evidence.py` 的解析规则） | `locator`+`quote`+`sha256` 的清单结构 |
| M2 | 布局模板（`layout.py` 的落点规则） | 纯函数约定 + `spec_sha16` 探针 |
| M3 | 规则词表与规则体（`connection_rules.json`） | 规则文件格式 + 审计器 + error⇒降级 的语义 |

具体怎么搬、往哪几个方向搬，见 `references/REUSE-GUIDE.md`（含 5 类可复用资产清单
与 4 步复用流程）。

## 6. 这份文件不能证明什么（诚实边界）

- 它**不能**证明本包在平台正式案例上得分更高——正式案例与白板由平台提供，本包不见；
- 它**不能**证明"M1+M2+M3 是唯一正确设计"——它只证明**拿掉这三层后，产物会丢掉
  可回溯性、可复现性与语义审计能力**（三项都有可执行的对照观测）；
- 下界实现 `bare_baseline.py` 是**一个**反例实现，不是"所有既有方案的代表"；
  换一个更聪明的既有方案，差距会缩小——但三层机制各自解决的可观测问题不会消失；
- 对照只跑了 apparatus 图类（route/flow/hybrid 未测），迁移性论断依据的是机制与题材解耦，
  不是实测。
