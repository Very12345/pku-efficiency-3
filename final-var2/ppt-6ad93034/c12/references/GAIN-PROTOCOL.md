# GAIN-PROTOCOL.md — 与基础 Agent 的公平对照协议、可测指标与实测记录

> **这份文档解决什么问题**：题面「使用增益 25 分」要求"在相同论文输入、相同模板和
> 相同运行条件下，加载成果后页面质量相比基础 Agent 是否提升"，并且**要求用公平对照
> 证明**——文字自述不算证据。本文件给出：① 两边条件如何做到**逐项可比**；
> ② 指标怎么算（含公式与可执行复核命令）；③ **本包真实跑出来的对照记录**；
> ④ 什么情况下本结论会被证伪。

> ⚠ **范围声明（先说清楚，避免误读）**：题面明确"对照结果由平台提供/生成"，
> 参赛者不提供白板。本文件**不声称**复现了平台的官方对照：下面记录的是
> **可在任何机器上复算的受控脚本级对照**（条件 B = 题面点名失败形态的确定性代理实现，
> 条件 S = 本 Skill 的真实流水线）。它的用途是给出**可证伪的下界**与可复现的测量口径，
> 而不是替代平台的 Agent 级对照。

## 1. 两个条件（逐项对齐）

| 对齐项 | 条件 B（baseline / 不加载 Skill） | 条件 S（skill / 加载本 Skill） | 是否一致 |
|-|-|-|-|
| 输入 | 同一 `case.json` | 同一 `case.json` | ✅ 同一文件 |
| 任务说明 | 同一 `task.md` | 同一 `task.md` | ✅ 同一文件 |
| 材料 | 同一 `material.*` | 同一 `material.*` | ✅ 同一文件 |
| 页数上限 | `spec.max_slides` | `spec.max_slides` | ✅ 读同一个 spec |
| 模板 | `spec.template` / `templates/default.json` | 同 | ✅ 同 |
| 语言/受众 | `spec.language` / `spec.audience` | 同 | ✅ 同 |
| 运行环境 | 同一 Python 解释器、同一 python-pptx / Pillow / matplotlib | 同 | ✅ 同一解释器 |
| 测量 | `references/measure_gain.py`（同一脚本、同一归一化口径） | 同 | ✅ 同一脚本 |
| 预算 | 单次运行脚本 <60 秒（Runtime contract 900 秒内） | 同 | ✅ 同一约束 |

**条件 B 的形态**（`measure_gain.py::build_baseline_deck`，确定性、无随机）：
按空行切段落块 → 每块一页；标题取段落首句；正文**整段原文照录**；
无页级叙事角色、无证据指针、无演讲备注、无预览、字号硬编码 18pt 不收敛。

> 这是题面 §1 点名失败清单的**代理实现**：*"把论文摘要或段落整段塞进文本框，
> 页面被压满"*、*"图注和图上标注对不上"*、*"导出 PDF 后字体被替换、文字溢出边界"*。
> 代理实现的价值在于**可复算**：任何人不依赖任何模型都能把同一段代码跑一遍。

## 2. 一条不许破的测量纪律

> **两侧用同一把尺子；"没做"的项按最差计，绝不为"没做"补分。**

具体到实现：
1. 每个指标都必须能用 `result.json` 或 `deck.pptx` 的字段**直接算出**，
   不依赖人工审美判断（避免"看起来更好"这类不可复算的结论）；
2. 条件 B 没有的字段（如角色、备注、证据脚注）一律记 **0**，不允许用
   "整段里其实包含这个信息"之类的理由折算成部分分；
3. 两侧都取**同一 case 的一次运行**，不挑最好的一次、不`--edit` 后再比；
4. 原始报告三件套随本文件一起留档（见 §6），任何人可重跑并逐格对拍。

## 3. 指标定义（质量 5 项 + 效率 3 项）

### 3.1 质量指标（进入对照结论）

| 编号 | 指标 | 精确定义 | 复核命令 |
|-|-|-|-|
| **Q1** | 页级角色覆盖率 | `deck.slides` 中 `role` 非空的页数 / 总页数 | `python -c "import json;d=json.load(open('<out>/result.json',encoding='utf-8'));s=d['deck']['slides'];print(sum(1 for x in s if x.get('role'))/len(s))"` |
| **Q3** | 数字主张可追溯率 | 含数字 token 的 `claims` 中 `evidence` 非空的比例（+ `unverified_claims` 应为 0 或有解释） | 同上路径统计 `claims[].evidence` |
| **Q4** | 演讲备注覆盖率 | `notes` 非空的页数 / 总页数（题面要求每页有讲稿/备注） | 同上，统计 `notes` |
| **Q5** | 证据脚注覆盖率 | `evidence_footer` 非空的页数 / 总页数（题面要求页级证据映射） | 同上，统计 `evidence_footer` |
| **Q6** | 可复核产物齐全度 | 七项交付物存在数 / 7：可编辑 PPTX、预览 PNG、预览 PDF、`evidence_map.md`、`evidence_map.json`、`manifest.json`（含全部 sha256）、`result.json` | `ls <out> <out>/preview <out>/work` |

数字 token 的归一化口径（两侧完全一致）：NFKC 规范化 → 去空白 → 转小写 →
匹配 `\d+(?:[.,]\d+)*\s*(?:%|％|倍|x|×)?`。与技能包
`scripts/evidence_check.py::find_numeric_tokens` 同口径。

### 3.2 效率指标（如实报出，不作为"赢"的依据）

| 编号 | 指标 | 定义 | 本包实测 |
|-|-|-|-|
| **E1** | 编辑粒度 | 改一页需要重做多少：`whole_deck_regenerate` / `local_op_with_version_archive` | B：整稿重生成；S：7 类局部 op |
| **E2** | 版本归档数 | `change_records` 条数（可回退的版本数） | B：0；S：≥1（`--edit` 时递增） |
| **E3** | 预览复查工件数 | 预览 PNG 张数 + PDF 是否产出 | B：0；S：页数 + 1 |

**注意（不许含糊）**：S 的**脚本耗时更长**（多出角色分配、数字核验、预览渲染、
sha256 清单），实测两个案例合计 **5.14 秒 vs 0.391 秒**。这是**成本不是收益**，
如实列出，不折算成"效率提升"。相对 900 秒 Runtime contract 预算，
5.14 秒占比 <1%，因此本包主张的是"**以可忽略的脚本开销换取可复核性**"，
**不主张**"比基础 Agent 更快"。

### 3.3 一个**不进入结论**的指标（说明为什么）

| 编号 | 指标 | 为什么不进结论 |
|-|-|-|
| Q2 | 单条文本长度合规率（≤90 字） | 它是**纪律的自我约束**度量。条件 B 只是照录材料段落，段落本身若很短就会"意外合规"（实测 1.0）；条件 S 反而可能因为某条主张 91 字而不达标。**用它做对照会得出误导性结论**，因此只如实报出、不参与判定。这条"自我设限反而吃亏"的指标被保留在报告里，正是为了不掩饰它。 |

## 5. 结论与**可证伪判据**

**结论（限定在受控脚本级对照内）**：在输入、模板、页数上限、解释器与测量脚本
完全相同的条件下，条件 S 在**五项可自动对拍的质量指标**上从基线形态的
`0/0/0/0/1-of-7` 提升到 `1/1/1/1/7-of-7`；代价是**每次运行多约 2–3 秒脚本时间**。

**本结论在什么情况下被证伪**（照此复核，不需要相信我）：

| # | 证伪条件 | 复核方式 |
|-|-|-|
| F-1 | 在**其他 `case.json`** 上重跑，Q1/Q3/Q4/Q5 中任一项 Δ ≤ 0 | 用 `references/measure_gain.py --case <你的 case>` 重跑，看报告 `aggregate.delta_mean` |
| F-2 | 条件 B 的产物里**实际存在**角色/备注/证据脚注字段 | 打开 `measure_gain.py` 的 `metric_baseline`：它对 B 的这些项**硬编码为 0**；只要 B 从未写这些字段，该指标即为 0 |
| F-3 | 条件 S 的 5 项里有任何一项不是**由真实产物算出**的 | 报告里每个数字都能在 `<out>/result.json` 里对应到字段；`Q6` 直接 `ls` 产物计数 |
| F-4 | 脚本耗时优势（若有人主张 S 更快） | 本文件已如实报出 S **更慢**；若复核测得 S 更快，说明环境不同，应重新记录而非套用本表 |
| F-5 | 条件 B 的代理实现被指"不是真 Agent" | **本文件一开始就承认这一点**（见范围声明）；它只提供可复算下界，不冒充平台对照 |

> 换句话说：本文件主张的是"**可复算下界 + 可证伪口径**"，
> 而不是"我们在平台的正式对照里赢了 X 分"。后者由平台生成，本包不提供。

## 7. 局限（诚实清单）

1. **样本量**：2 个案例（1 示例 + 1 留出）。平台会用 3 个固定案例 × 3 次重复，
   本表不能替代那 9 次运行。
2. **条件 B 是代理实现**，不是真实基础 Agent 的输出；真实基础 Agent 可能自己
   写出备注或角色（那正是"使用增益"要区分的部分）。因此本表是**下界**。
3. **未覆盖人工返工量**：题面提到"减少返工页数、重排次数、导出复查轮次或整体
   人工修改量"，本包只能给出**可记录的代理量**（E1 编辑粒度、E2 版本归档、
   E3 预览复查工件），真实人工小时数需要人在环测量，本包不编造。
4. **未做审美评价**：五项指标刻意全部避开审美（题面也要求"前四项不需要人工
   审美判断"），因此本表**不能**用来主张"页面更好看"。
5. **Q2 的负面结果被保留**：见 §3.3 与案例 B —— 如实保留，不做选择性报告。
